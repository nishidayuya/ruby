# frozen-literal-magic-comment 要件定義書（軽量版）

## 概要

Rubyに新しいマジックコメント `# frozen_literal: true` を導入し、ソースファイル内のすべてのリテラル（文字列、配列、ハッシュ）をデフォルトでフリーズされた状態にします。

## 主要機能要件

**【信頼性レベル凡例】**:
- 🔵 **青信号**: 既存の `frozen_string_literal` の実装を参考に確定した要件
- 🟡 **黄信号**: 既存仕様からの妥当な推測による要件
- 🔴 **赤信号**: 推測による要件（仕様確認が必要）

### 必須機能（Must Have）

- **REQ-001: 文字列リテラルのフリーズ** 🔵
  - `# frozen_literal: true` が指定された場合、文字列リテラルはフリーズされる。
  - これは `# frozen_string_literal: true` と同等の挙動。
- **REQ-002: 配列リテラルのフリーズ** 🔵
  - `[1, 2, 3]` などの配列リテラルは、コンパイル時にフリーズされたオブジェクトとして生成される。
- **REQ-003: ハッシュリテラルのフリーズ** 🔵
  - `{a: 1}` などのハッシュリテラルは、コンパイル時にフリーズされたオブジェクトとして生成される。
- **REQ-004: マジックコメントの認識** 🔵
  - `parse.y` で `# frozen_literal: true` を認識し、コンパイラフラグに伝播させる。

### 基本的な制約

- **REQ-401: 既存機能との互換性** 🟡
  - `# frozen_string_literal: false` が同時に指定された場合、個別の設定を優先するか、`frozen_literal` が上書きするかを決定する必要がある。（暫定：より広範な `frozen_literal` の設定に従う）

## 簡易ユーザーストーリー

### ストーリー1: 意図しない破壊的変更の防止

**私は** Ruby開発者 **として**
**ソース内のリテラルをすべてフリーズさせたい**
**そうすることで** 意図しないリテラルの変更によるバグを防ぎ、メモリ使用量を最適化できる。

**関連要件**: REQ-001, REQ-002, REQ-003

## 基本的な受け入れ基準

### REQ-002: 配列リテラルのフリーズ

**Given（前提条件）**:
- ファイルの先頭に `# frozen_literal: true` が記述されている。

**When（実行条件）**:
- `a = [1, 2, 3]` を実行する。

**Then（期待結果）**:
- `a.frozen?` が `true` を返す。

**テストケース**:
- [ ] 正常系: 配列リテラルがフリーズされていること 🔵
- [ ] 正常系: ネストしたリテラル（例：`[[1]]`）もフリーズされていること 🟡

## 最小限の非機能要件

- **パフォーマンス**: 配列やハッシュの生成コストを抑えるため、可能な限りコンパイル時にフリーズオブジェクトを共有する 🔵
- **セキュリティ**: 不変性の保証によるセキュリティの向上 🔵
